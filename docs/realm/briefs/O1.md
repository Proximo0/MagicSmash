# Job O1: running it
Owns `realm/ops/` (new), `docs/realm/ops.md`, and small hooks in the server/gateway main.rs for flags and metrics.
Read the plan row O1 and `docs/realm/world.md` if present, `realm/README.md`.
Build, for a realm hosted on Curtis's Windows PC now and a rented Linux box later: a host package (one folder: gateway,
server, store tools, config file with every setting documented, start/stop scripts for Windows .cmd/.ps1 and Linux
systemd unit), structured logs with rotation, a metrics endpoint on loopback (players, fields, tick ms p50/p99, queue,
store write latency, errors) plus a text status page, alarms (log lines + a hook script) on tick budget breach, store
errors, host death; backups on a clock (SQLite online backup, keep N, verify each by opening it and running verify)
and a restore drill script; kill switches (close login, freeze trade/market, stop a field kind) from the admin console;
release and rollback (versioned folders, a switch script that keeps the store, refuses a store schema downgrade);
flood protection at the socket (per-IP connection and packet rate limits). Proof: a test that runs a release, a
rollback and a restore end to end on a temp folder (on Linux in CI; the .ps1 path checked by a Windows CI step if
cheap), and the station word `ops` that rehearses backup and restore on the Ubuntu station nightly.
