# Job W1: the wire, the gateway and the field hosts
Owns `realm/server`, new crate `realm/gateway` (add it to the workspace; it may depend on `realm/store` as a path dep).
Rules: rules.md sections 1, 2, 7, 12; store.md "The trait" and "Who may run what" (mail to another player and a
player's own spends go through the server, so the gateway must offer them).
Build:
1. The two-byte input (`IN_DIR`, `IN_SKILL1/2`, `IN_ULT`, `IN_INTERACT`, picks and potions in byte 1) and the hero's
   `Sheet` on the wire, replacing `realm_server::wire_input`'s one byte and the HELLO's class 0..4 shortcut. Keep the
   client side (`server/src/client.rs`, `predict.rs`) in step so `realm/check_client.sh` still passes 20/20.
2. From Job G: repeat a tick only after one round trip.
3. The gateway: dev login (name only, behind a `--dev-login` flag; Steam tickets come later in P1), character list,
   create/delete hero, town rooms (snapshot protocol, chat lines in a room), field tickets that hand a hero to a field host.
4. Field hosts: one thread group per field copy; a hero's outing result (haul, xp, potions used) is applied to the
   store when the hero leaves by gate or waystone, falls, or disconnects; carry her final outing in the LEAVE event
   (the core empties the slot on LEAVE).
5. Store calls players need: bank deposit/withdraw, mail, own spends, all through `ops::who_may`.
Proof (a test or `realm-loadtest` mode): bots log in, make heroes, fight, bank, log out and back in; a server killed
mid-outing loses nothing banked (kill the process in the test, reopen the store, `verify`). Add a `soak` word to
`tools/station/station.sh` (bots through the wire server for 2 hours, one summary line) and its role in
`tools/station/roles.txt` for `ubuntu`. Doc: `docs/realm/wire.md`.
